# Loading immune receptor data into scirpy

When importing immune receptor data, the end goal is to produce a `AnnData` object. When gene expression (RNA-seq) data are also available, the goal is to merge these modalities into a single `MuData` object, where `gex` modality describes RNA-seq data and `airr` modality describes AIRR-seq.

When working with multiple samples, it is desirable to merge them all into a unified `MuData`.

Creating an `AnnData` or `MuData` is a **required** first step before any downstream analysis. If you are not sure of the origin of data or how to import it, ask user.

## Setup

```python
import anndata
import muon as mu
import pandas as pd
import scanpy as sc
import scirpy as ir
```

## The scirpy data model (assumptions for all analyses)

- Chain loci must be valid: `TRA`, `TRG`, `IGK`, `IGL` (VJ-junction chains) or `TRB`, `TRD`, `IGH` (VDJ-junction chains).
- Each cell may have up to two VJ and two VDJ chains (dual IR). Excess chains (lowest read/UMI count) are dropped and the cell is flagged as a multichain-cell.
- Non-productive chains are ignored. CellRanger, TraCeR, and the AIRR format flag these automatically; for custom formats you must pass the `productive` flag or filter beforehand.

## Data loading

### AIRR data

All of the functions below return an `AnnData` object unless specified otherwise.

#### Determining what data you have

##### 10X Genomics Cell Ranger
If you have files like `{all,filtered}_contig_annotations.csv`, `all_contig_annotations.json`, that's 10X Genomics cell-ranger data. Compressed data and various prefixes are allowed (e.g. `GSM000001_filtered_contig_annotations.csv.gz`).

Use `scirpy.io.read_10x_vdj(path, filtered=True, include_fields=None, **kwargs)`.

`path (str | Path)` – Path to `filtered_contig_annotations.csv`, `all_contig_annotations.csv` or `all_contig_annotations.json`.

`filtered (bool (default: True))` – Only keep filtered contig annotations (i.e. is_cell and high_confidence). If using `filtered_contig_annotations.csv` already, this option is futile.

##### TraCeR
If you have a directory with structure like this:
* <directory>/<cell_name>/aligned_reads
* <directory>/<cell_name>/Trinity_output
* <directory>/<cell_name>/IgBLAST_output
* <directory>/<cell_name>/unfiltered_TCR_seqs
* <directory>/<cell_name>/expression_quantification
* <directory>/<cell_name>/filtered_TCR_seqs

That's TraCeR data. You need only `filtered_TCR_seqs/<CELL_ID>.pkl` files to be present. If the user asks you to use the results of `tracer summarise`, those data won't work, per scirpy doc: "Unfortunately the results files generated by tracer summarize do not contain all required information."

Use `scirpy.io.read_tracer(path, **kwargs)`.

`path (str | Path)` – Path to the TraCeR output folder.

##### BraCeR
The directory structure can be similar to TraCeR but you have
* <directory>/<cell_name>/unfiltered_BCR_seqs
* <directory>/<cell_name>/filtered_BCR_seqs

Unlike with TraCeR, here you actually need the output of `bracer summarise`. Look for a file `changeodb.tab` in `<directory>/filtered_BCR_summary` or `<directory>/unfiltered_BCR_summary`. Alternatively, it can just be provided by user with the note that it's BraCeR.

Use `scirpy.io.read_bracer(path, **kwargs)`.

`path (str | Path)` – Path to the changeodb.tab file.

##### AIRR rearrangement format
If you have a tsv file with the following fields:
* `cell_id`
* `productive`
* `locus` containing a valid IMGT locus name
* at least one of `consensus_count`, `duplicate_count`, or `umi_count`
* at least one of `junction_aa` or `junction`.

Import as AIRR rearrangement data.

Use `scirpy.io.read_airr(path, use_umi_count_col=None, infer_locus=True, cell_attributes='is_cell', include_fields=None, **kwargs)`

`path (str | Sequence[str] | Path | Sequence[Path] | DataFrame | Sequence[DataFrame])` – Path to the AIRR rearrangement tsv file. If different chains are split up into multiple files, these can be specified as a List, e.g. [`"path/to/tcr_alpha.tsv"`, `"path/to/tcr_beta.tsv"`]. Alternatively, this can be a pandas data frame.

`use_umi_count_col (None (default: None))` – Deprecated. Has no effect.

`infer_locus (bool (default: True))` – Try to infer the locus column from gene names, in case it is not specified.

`cell_attributes (Collection[str] (default: 'is_cell'))` – Fields in the rearrangement schema that are specific for a cell rather than a chain. The values must be identical over all records belonging to a cell.

`include_fields (Any (default: None))` – Deprecated. Has no effect.

##### BD Rhapsody
If you have files like this: `*_perCellChain.csv`, `*_perCellChain_unfiltered.csv`, `*_VDJ_Dominant_Contigs.csv`, and `*_VDJ_Unfiltered_Contigs.csv` or their gzipped versions, that's BD Rhapsody data. `*_perCell.csv` is not supported.

Use `scirpy.io.read_bd_rhapsody(path, **kwargs)`

`path (str | Path)` – Path to the perCellChain or Contigs file generated by the BD Rhapsody analysis pipeline.

##### Dandelion
If you have a prepared Python code that initializes a `dandelion.Dandelion` instance, you can import it via `from_dandelion`

Use `scirpy.io.from_dandelion(dandelion, transfer=False, to_mudata=False, **kwargs)`.

`dandelion` – a dandelion.Dandelion instance

`transfer (bool (default: False))` – Whether to execute dandelion.tl.transfer to transfer all data to the anndata.AnnData instance.

`to_mudata (bool (default: False))` – Return MuData object instead of AnnData object.

### RNA data

All of the functions below return an `AnnData` object unless specified otherwise.

#### Determining what data you have

##### 10X Genomics

If you have a `.hdf5` file and you know that it's 10X Genomics, use

`scanpy.read_10x_h5(filename, *, genome=None, gex_only=True, backup_url=None)`

`genome: str | None (default: None)` - Filter expression to genes within this genome. For legacy 10x h5 files, this must be provided if the data contains more than one genome.

`gex_only: bool (default: True)` - Only keep ‘Gene Expression’ data and ignore other feature types, e.g. ‘Antibody Capture’, ‘CRISPR Guide Capture’, or ‘Custom’

If you see a directory with files:
* `*_.barcodes.tsv`
* `*_.genes.tsv`
* `*_.matrix.mtx`

That's 10X mtx data. If these files are gzipped, unzip them first if you encounter import errors. Use

`scanpy.read_10x_mtx(path, *, var_names='gene_symbols', make_unique=True, cache=False, cache_compression=_empty, gex_only=True, prefix=None, compressed=True)`

`path: PathLike[str] | str` - Path to directory for .mtx and .tsv files.

`var_names: Literal['gene_symbols', 'gene_ids'] (default: 'gene_symbols')` - The variables index.

`make_unique: bool (default: True)` - Whether to make the variables index unique by appending ‘-1’, ‘-2’ etc. or not.

`gex_only: bool (default: True)` - Only keep ‘Gene Expression’ data and ignore other feature types, e.g. ‘Antibody Capture’, ‘CRISPR Guide Capture’, or ‘Custom’

`prefix: str | None (default: None)` - Any prefix before matrix.mtx, genes.tsv and barcodes.tsv. For instance, if the files are named `patientA_matrix.mtx`, `patientA_genes.tsv` and `patientA_barcodes.tsv` the prefix is `patientA_`.

`compressed: bool (default: True)`
Whether to expect Cell Ranger v3+ files (.mtx, features.tsv, barcodes.tsv) to be gzipped. If True, ‘.gz’ suffix is appended to filenames. Set to False for STARsolo output. Has no effect on legacy (v2-) files.

If you have 10X Genomics visium dataset, use

`scanpy.read_visium()`

##### .h5ad

If you have `.h5ad` file, use

`scanpy.read_h5ad()`

##### .csv

If you have a `.csv` file, use

`scanpy.read_csv()`

##### .xlsx

If you have an `.xlsx` file, use

`scanpy.read_excel()`

Assumes that the first columns stores the row names and the first row the column names.

##### .h5
If you have an `.h5` (hdf5) file, use

`scanpy.read_hdf()`

##### .loom
If you have a .loom-formatted hdf5-file, use

`scanpy.read_loom()`

##### .mtx
If you have a .mtx-file, use

`scanpy.read_mtx()`

##### .txt
If you have a .txt, .tab, .data file, use

`scanpy.read_text()`

##### umi-tools
If you have a gzipped condenset count matrix from umi_tools, use

`scanpy.read_umi_tools()`

### Building a MuData

Typical loading workflow looks like this:

```python
# Load the TCR data, AnnData object
adata_tcr = ir.io.read_10x_vdj("example_data/liao-2019-covid19/GSM4385993_C144_filtered_contig_annotations.csv.gz")

# Load the associated transcriptomics data, AnnData object
adata = sc.read_10x_h5("example_data/liao-2019-covid19/GSM4339772_C144_filtered_feature_bc_matrix.h5")
adata.var_names_make_unique()

# Unite them into a single MuData
mdata = mu.MuData({"gex": adata, "airr": adata_tcr})
```

### Combining multiple samples
Load each sample independently, then unite the `AnnData`s using `anndata.concat()`

```python
import glob

# define sample metadata. Usually read from a file.
samples = {
    "C144": {"group": "mild"},
    "C146": {"group": "severe"},
    "C149": {"group": "healthy control"},
}

# Create a list of AnnData objects (one for each sample)
adatas_tcr = {}
adatas_gex = {}
for sample in samples.keys():
    gex_file = glob(f"example_data/liao-2019-covid19/*{sample}*.h5")[0]
    tcr_file = glob(f"example_data/liao-2019-covid19/*{sample}*.csv.gz")[0]
    adata_gex = sc.read_10x_h5(gex_file)
    adata_tcr = ir.io.read_10x_vdj(tcr_file)
    # concatenation only works with unique gene names
    adata_gex.var_names_make_unique()
    adatas_tcr[sample] = adata_tcr
    adatas_gex[sample] = adata_gex

# Merge anndata objects
adata_gex = anndata.concat(adatas_gex, index_unique="_")
adata_tcr = anndata.concat(adatas_tcr, index_unique="_")
mdata = mu.MuData({"gex": adata_gex, "airr": adata_tcr})

# Set global metadata on `mdata.obs`
mdata.obs["sample"] = mdata.obs_names.to_series().str.split("_", expand=True)[1]
mdata.obs["group"] = mdata.obs["sample"].map(lambda x: samples[x]["group"])
```
